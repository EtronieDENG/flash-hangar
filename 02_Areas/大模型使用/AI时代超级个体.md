### 一、 如何用 AI 搭建你的“三省六部”？

在传统工作流中，一个人容易犯错，是因为你同时兼任了“决策、审核、执行”——这极易产生思维盲区。引入 AI 后，你可以把不同的 Prompt / Model 设定为不同的职能部门，实现**决策权与执行权的物理分离**：

|**部门**|**对应 AI 的角色设置**|**核心职责**|**实际操作示例**|
|---|---|---|---|
|**中书省**（决策/起草）|**生成型 AI**（如 Claude、GPT-4o）|负责根据你的意图，草拟方案、撰写代码、生成创意提案。|提示词：“请根据我的需求，起草一份产品规划方案/代码骨架。”|
|**门下省**（审议/封驳）|**批判型 AI**（设置了硬核审核 Rules 的 Agent）|**最关键的一环。** 专门负责找茬、逻辑校验、合规检查。如果觉得方案不可行，**直接退回**。|提示词：“不要附和，严格审查以上方案的逻辑漏洞、成本风险与安全隐患，列出致命缺陷。”|
|**尚书省**（行政总调度）|**工作流自动化工具**（如 Dify、n8n、AutoClaw / OpenClaw）|负责把审核通过的指令，分发给具体的工具去落实执行。|自动化 Workflow：“方案审查无误后，自动触发下游 API 节点。”|
|**六部**（具体执行单元）|**专职 API / 细分 Agent**|吏部（权限管理）、户部（数据与财务分析）、兵部（爬虫/自动化工具执行）等。|垂直领域小模型或具体工具函数（Function Calling）。|

### 二、 你的“科举制”：如何遴选与升级 Skills / Prompts？

你提到的“科举制就是别人做好的 Skills”非常到位。

在开源社区（如 GitHub、Dify 社区、Claw 市场等）里，每天有海量的 Prompt、MCP（Model Context Protocol）或 Workflow 被开发出来。这就是你的“应试举子”。

作为“皇帝”，你不能把所有 Skills 都一股脑塞进你的上下文（Context Window），那会导致 AI 产生混乱（“朝政混乱”）。你需要建立你的“科举选拔机制”：

1. **童试/乡试（初步筛选）**：在沙盒环境中测试社区提供的开源 Skill，验证其能否稳定输出，淘汰写得过于笼统、包含幻想（Hallucination）的废柴 Prompt。
    
2. **殿试（标准化集成）**：挑选出最稳定、最符合你业务逻辑的 Skill，封装为你本地或工作流中的标准 Prompt 模板（System Prompt），授予“官职”（赋予具体的系统调用权限）。
    
3. **官僚考核（定期更新）**：随着底层大模型（LLM）的升级，定期淘汰旧的 Prompt 逻辑，用更新、更高效的 Agent 替代。
    

### 三、 这套架构最核心的防呆机制：“避免独裁与失误”

你之前在与 AI 交互时强调过“优先指出逻辑漏洞、禁止顺着我说、保持批判性”**，这本质上就是你在为自己的 AI 系统建立**“门下省的封驳权”。

普通人使用 AI，往往是“我提问，AI 回答”，这相当于皇帝直接找了个谄媚的奸臣，AI 顺着用户的错误假设一路狂奔（“外戚专权”）。

而一个成熟的人利用 AI 搞“三省六部”：

1. **输入需求**后，先让 **中书 Agent** 给出方案；
    
2. 强行要求 **门下 Agent** 进行黑盒测试与对抗性质询（Red Teaming）；
    
3. **你（皇帝）** 只需要审阅门下省提交的质询报告，做最后的“御批”；
    
4. 批准后，由 **尚书 Agent** 调度代码或 API 去自动化落地。
    

通过这种架构，你一个人就拥有了过去需要一个十几人精英团队才能支撑的**决策、质询、执行与纠错系统**。
