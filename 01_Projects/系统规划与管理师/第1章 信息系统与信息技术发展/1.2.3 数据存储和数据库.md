## 一、数据存储技术架构（五个组成部分）

从底层到上层由五部分组成：

| 组成 | 内容 |
| --- | --- |
| <span style="white-space: nowrap;">**存储介质**</span> | 机械硬盘 HDD、固态硬盘 SSD、磁带、光盘 |
| <span style="white-space: nowrap;">**组网方式**</span> | IP 组网、FC 光纤组网、IB 无线带宽组网 |
| <span style="white-space: nowrap;">**存储类型和协议**</span> | 文件存储、块存储、对象存储 |
| <span style="white-space: nowrap;">**存储架构**</span> | 集中式存储、分布式存储（存储集群） |
| <span style="white-space: nowrap;">**连接方式**</span> | **DAS / NAS / SAN**（见下） |

## 二、DAS / NAS / SAN 对比（必考）⭐⭐⭐

| 维度 | <span style="white-space: nowrap;">**DAS**</span> | <span style="white-space: nowrap;">**NAS**</span> | <span style="white-space: nowrap;">**SAN**</span> |
| --- | --- | --- | --- |
| 全称 | 直接附加存储 | 网络接入存储 | 存储区域网络 |
| 传输协议 | SCSI / FC / ATA | TCP/IP | FC（光纤通道） |
| 传输对象 | **数据块** | **文件** | **数据块** |
| 文件共享 | 否（主机自管文件系统） | 是（NFS/CIFS） | 否 |
| 异种 OS 共享 | 否 | 是 | 否 |
| 安装难易 | 不一定 | **简单** | **困难** |
| 灾难忍受度 | 低 | 高 | 高（专有方案） |
| 适合对象 | 中小组织 / SOHO / 服务器少 | 文档共享高、异质格式 | 大型组织 / 数据中心 / 数据库 |
| 容量扩充 | 低 | 中 | 高 |

💡 一句话区分：**DAS 直连主机难共享；NAS 走 TCP/IP 以文件共享、易用；SAN 用 FC 建高速专用存储网、适合大型数据库**。

## 三、数据结构模型（三种）⭐⭐

| 模型 | 结构 | 特点 |
| --- | --- | --- |
| <span style="white-space: nowrap;">**层次模型**</span> | 树结构 | 最早使用，实体间用"树"表示关联 |
| <span style="white-space: nowrap;">**网状模型**</span> | 有向图 | 实体间"多对多"关联 |
| <span style="white-space: nowrap;">**关系模型**</span> | 二维表 | **主流**，用表表示实体及关联 |

💡 层次模型 + 网状模型 统称为**格式化数据模型**。

## 四、关系型 vs NoSQL ⭐⭐

- **关系型数据库（ACID）**：基于关系模型，事务特性强（原子性、一致性、隔离性、持久性）。
- **NoSQL（非关系型）**：不需要固定表结构、通常无连接操作；含**键值、列存储、文档、图**等类型；**高并发、易扩展**，但事务能力较弱；在大数据存取上有关系型无法比拟的性能优势。

### 4.1 NoSQL 四类 + 列式存储详解 ⭐⭐

| 类型 | 数据模型 | 典型代表 | 特点 |
| --- | --- | --- | --- |
| <span style="white-space: nowrap;">**键值 Key-Value**</span> | 键值对 | Redis、Berkeley DB | 最简单，高并发读写 |
| <span style="white-space: nowrap;">**列存储 Columnar**</span> | 按列 / 列族存储 | HBase、Cassandra、Bigtable、ClickHouse | 同列连续存，压缩高、聚合快 |
| <span style="white-space: nowrap;">**文档 Document**</span> | 类 JSON / BSON | MongoDB、CouchDB | 结构灵活，半结构化 |
| <span style="white-space: nowrap;">**图 Graph**</span> | 节点 + 边 | Neo4j | 关系网络，多对多关联 |

**列式存储数据库（Columnar / Column-family）是什么** ⭐⭐
- **核心**：不按"行"存，而是把**同一列的数据连续存放**；读取时只取查询需要的列，不读整行。
- **对比行存储**：
  - 行存储（关系型 DB）：一条记录各字段连续存 → 适合 **OLTP**（整行增删改查频繁）。
  - 列存储：同列值连续存 → 适合 **OLAP / 分析**（只对少数几列做海量聚合统计）。
- **优点**：① 高压缩比（同列数据类型一致）；② 聚合 / 扫描查询快；③ 适合读多写少的分析场景。
- **缺点**：单行插入 / 更新慢（要写多个列位置），不适合高频事务写。
- **典型代表**：HBase、Cassandra（宽列/列族）、Bigtable、ClickHouse（分析型列存）。
- **关联考点**：列存储常出现在"大数据"章节（1.3.4）——HBase 构建在 HDFS 之上，是大数据生态的典型列存储数据库。

## 五、数据仓库（了解）

- 定义：面向主题的、集成的、非易失的、随时间变化的数据集合。
- 分类：ROLAP（基于关系库）、MOLAP（基于多维库）、HOLAP（混合）。

## 六、本节自测

1. 下列存储模式中，通过 TCP/IP 以"文件"方式提供存储服务、支持异种操作系统文件共享的是（ ）（选择）
   A. DAS  B. NAS  C. SAN  D. 以上都不是

2. 下列关于 SAN 的描述，正确的是（ ）（选择）
   A. 用 TCP/IP 传输文件  B. 用 FC 构建高速专用存储网络、传输数据块  C. 主机直接管理文件系统

3. 目前主流的数据库数据结构模型是（ ）（选择）
   A. 层次模型  B. 网状模型  C. 关系模型（二维表）  D. 格式化模型

4. 关系型数据库与 NoSQL 的主要区别是什么？（各举一关键词）

5. 列式存储数据库相比传统行存储的关系型数据库，主要优势是什么？（选择）
   A. 单行更新更快  B. 同列连续存放、压缩比高、聚合查询快  C. 更适合高频事务写  D. 必须固定表结构

<details><summary>答案</summary>

1. **B**（NAS：TCP/IP + 文件 + 异种 OS 共享）
2. **B**（SAN：FC、数据块、高速专用网；A 是 NAS，C 是 DAS）
3. **C**
4. 关系型基于关系模型、事务强（ACID）；NoSQL 无固定表结构、高并发易扩展但事务弱（如键值/列存储/文档/图）
5. **B**（列式把同列值连续存放 → 压缩高、聚合/分析查询快；A、C 是行存储优势；D 是关系型特征）
